AFTER THE WORKFLOW · FAILURE CONTROLS

CUSTOMER DESIGN / REFERENCE ARCHITECTURE

It advises. It does not act.

Built for what happens when it fails. Three agents read the radio traffic and write a short briefing. Each fact is checked against the original message. If a responder says he is not sure, the agent leaves it out. If the AI stops working, the messages are still there.

What this demo is: synthetic voice clips with transcripts written in advance. A real service would need permission to use agency audio, speech-to-text that has been tested and measured, policy controls, and a voice path that keeps working even if the AI does not.

Demo: a scripted draft or optional model draft; a responder must verify it against the source.
Extending the same pattern across the Unified Communications portfolio

The three-agent contract — extract with a source ID, review each claim against its origin, draft only from approved claims — is modality-independent. The intake changes; the governance does not.

PTT

Voice transmissions

Speech-to-text per transmission; the source ID is the transmission itself. Demonstrated here.

MCVIDEO

Video events

Frame and clip events become claims with a timestamp and camera ID as the source. A responder verifies against the original clip, exactly as with audio.

MCDATA

Messages and forms

Text messages, status updates and structured field data are already machine-readable, so Signal extraction is simpler and Safety review is stricter about turning a request into a completed action.

LOCATION

Unit position and status

Position and availability are corroborating context rather than claims: they can support or contradict a stated fact, and should never originate one.

Scope note: this demo implements the PTT path only. The other modalities are design intent, not working code.

What happens when AI fails?

The primary voice path stays independent from inference. The assistant withholds untrusted advice and retains the source.

Normal path

Communications continue through the existing service. Signal, Safety and Briefing produce an advisory draft with links to the original source messages.

Degraded path

Timeout, no approved facts, unclear speech or network loss withholds a new draft. Keep original communications and show the reason.

Security boundary

Access by role and incident. Retain source provenance and audit; apply agency deployment and retention rules.

Operate the speech and three-agent service.

Production needs approved speech data, versioned prompts and models, fact-level evaluations, monitoring and rollback owners.

01 / BASELINE

Representative data

Languages, accents, radio codecs and noisy incident conditions.

Agree on consent, retention and a human-reviewed test set.
02 / VALIDATE

Measure failure

Speech error, missed facts, unsupported facts, Safety false approvals, source accuracy and per-agent latency.

Set release thresholds with responders and safety owners.
03 / RELEASE

Control change

Version speech models, agent prompts and output schemas; gate each change with replay tests and a small canary.

Compare against the previous approved version.
04 / OPERATE

Watch and recover

Monitor per-agent errors, quality drift, operator corrections, cost and timeouts; roll back a prompt or model if needed.

Keep an owner, on-call procedure and audit record.

LEADERSHIP / DELIVERY PLAN

Small scope first. Evidence before rollout.

The architect aligns operations, product, speech/ML engineering, security and the customer around one three-agent use case: an advisory catch-up for a late responder with source verification and fallback.

01 / DISCOVER

Agree on the problem

Interview dispatch and field teams. Identify authorized PTT/LMR media interfaces, recording rights, incident identifiers, data boundaries and responder acceptance criteria.

Owners: Product + operations
Gate: approved use case and success measures
02 / PROVE

Test with past incidents

Build the authorized speech-to-text path and three-agent handoff. Replay approved incidents and measure transcription, fact-level Safety decisions, sources and latency.

Owners: ML + domain experts
Gate: agreed quality and latency thresholds
03 / PILOT

Keep humans in control

Pilot advisory drafts with a small responder group. Monitor rejected facts, corrections, latency and fallbacks; rehearse voice-path independence.

Owners: Engineering + security
Gate: safety review and support readiness
04 / RELEASE

Operate and improve

Version prompts and models, observe drift, train reviewers and exercise rollback. Expand only when agreed quality and safety gates pass.

Owners: Product + SRE + customer
Gate: measurable benefit and owner sign-off
Principal architect decision: prioritize a three-agent late-join briefing because each extracted fact can be reviewed against the original transmission. Keep dispatch and talkgroup control outside this advisory service.
